Round 2 · corrected brief

Make it confident, not calm.

Round 1 was briefed from a product design system built for an app that handles people's money — where the UI should recede so the numbers feel trustworthy. That was the wrong instruction for a portfolio. A portfolio has about four seconds to impress. This round corrects it.

What was wrong

  • Nine sections, one recipe: hairline → heading → subtitle → grid of bordered white cards. That is monotony, not minimalism.
  • The hero described the work instead of showing it, with ~40% of the viewport empty.
  • The best asset — real client storefronts — appeared as small cropped thumbnails.
  • Flagship work and minor work carried nearly identical visual weight.
  • Type compressed into a narrow 15–30px band. No scale contrast anywhere.

The tools this round

  • Scale. A real display size (60px+) against small mono labels.
  • Contrast. Alternate light and full-bleed dark bands so sections stop blurring together.
  • Screenshots as hero. Big, browser-framed, sometimes bleeding off the edge.
  • Depth. Layering and a real lift shadow — not glassmorphism, which we removed on purpose.
  • One accent still. Restraint in colour, boldness in scale and composition.

Still true from Round 1

Light + dark both required. Tabular numerals on every metric. No hype, no countdowns, no gradient text, no generic-SaaS template feel, no return to the old terminal look. Honest status: some systems are in production, one is staging-only.

How to use these cards

The decisive cards ship as three variants each — Hero A/B/C, Systems index A/B/C, Case-study hero A/B/C — drawn against real screenshots. Pick a direction per card, or mix. Token names match src/index.css, so an accepted design ports straight back.
